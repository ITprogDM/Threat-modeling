## ⚠️ STRIDE

---

### 🔐 Аутентификация и 2FA

#### 1. Пользователь → Nginx (API Gateway)

| Домен | Описание угрозы |
|-------|----------------|
| **I** | В логах NGINX оседает чувствительная информация (токены сессии и др.) |
| **R** | Отсутствует качественное логирование (кто и откуда выполняет действие) |
| **D** | Отсутствие Rate Limiting → возможность перегрузить шлюз и вызвать DoS |

---

#### 2. Nginx → AuthService

| Домен | Описание угрозы |
|-------|----------------|
| **S** | Кража токена сессии, Brute Force, Brute Force OTP → выдача себя за другого пользователя |
| **T** | Использование HTTP → атаки MITM, подмена данных |
| **R** | Отсутствует логирование (успешная / неуспешная аутентификация, изменение данных) |
| **I** | Утечка данных из-за HTTP |
| **D** | Отсутствие Rate Limiting и лимитов подключений |
| **E** | Отсутствует валидация данных на бэкенде |

---

#### 3. AuthService → Postgres

| Домен | Описание угрозы |
|-------|----------------|
| **T, I, E, D** | SQL-инъекции |
| **I** | Данные в БД хранятся в открытом виде |
| **R** | Отсутствует логирование действий в БД |

---

#### 4. AuthService → Redis

| Домен | Описание угрозы |
|-------|----------------|
| **S** | Подмена OTP |
| **T** | Изменение OTP |
| **R** | Передача OTP по HTTP, отсутствие логирования |
| **E** | Возможность отключения проверки по OTP |

---

### 💳 Оплата / Перевод

#### 1. Пользователь/Мерчант/Платёжная система → Nginx

| Домен | Описание угрозы |
|-------|----------------|
| **I** | В логах NGINX оседает чувствительная информация |
| **R** | Отсутствует качественное логирование (кто, откуда, какое действие) |
| **D** | Отсутствие Rate Limiting → риск DoS |

---

#### 2. Nginx → Processing / Payment-GW / Antifraud / Transaction / Account Service

| Домен | Описание угрозы |
|-------|----------------|
| **S** | Подмена инициатора запроса → отсутствует валидация вызывающего сервиса |
| **T** | Атаки MITM из-за HTTP |
| **R** | Отсутствие логирования действий и данных по платежам |
| **I** | Раскрытие CVV, PAN, срока действия карты через HTTP |
| **D** | Отсутствие балансировщика и Rate Limiting → отказ системы |
| **E** | Отсутствует валидация запросов на бэкенде и источника запроса |

---

#### 3. Processing / Antifraud → Kafka

| Домен | Описание угрозы |
|-------|----------------|
| **S** | Подмена события при отправке в Kafka (из-за HTTP) |
| **T** | Изменение сообщения в Kafka (из-за HTTP, отсутствия валидации) |
| **R** | Отсутствие логирования |
| **I** | Передача чувствительных данных в открытом виде по HTTP |
| **D** | Перегрузка топиков → DoS |

---

#### 4. Processing Service → Postgres

| Домен | Описание угрозы |
|-------|----------------|
| **T, I, E, D** | SQL-инъекции |
| **I** | Данные в БД хранятся в открытом виде |
| **R** | Отсутствует логирование действий в БД |
