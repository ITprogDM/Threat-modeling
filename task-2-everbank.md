# Threat Model — EverBank

##  Границы доверия

| № | Границы |
|---|------------|
| 1 | Пользователь/Внешняя платёжная система/Оператор банка/Мерчант → Nginx (API Gateway) |
| 2 | Nginx (API Gateway) → Services (payment-gw/notification/auth-service/kyc/stories/reporting-service/profile/forum/admin-panel/transaction/account-service/card-service) |
| 3 | Services (payment-gw/notification/auth-service/kyc/stories/reporting-service/profile/forum/admin-panel/transaction/account-service/card-service/processing-service/antifraud-service) → Kafka |
| 4 | Services (notification/auth-service/kyc) → Redis |
| 5 | Services (stories/kyc) → minio |
| 6 | Services (auth-service/kyc/stories/reporting-service/profile/forum/admin-panel/account-service/card-service/processing-service) → Postgres |

# Модель угроз

| # | STRIDE | Элемент(ы) диаграммы | Описание элемента | Угроза | Сценарий реализации | Критичность | Защита | Требование (задача) |
|---|---|---|---|---|---|---|---|---|
| 1 | Spoofing | `Operator` → `admin-panel` | Оператор входит в бэк-офис по отдельному логину и паролю | Компрометация учётной записи оператора позволяет получить доступ к бэк-офису | Атакующий перебирает пароль через `/login` или использует утёкшие credentials | Высокая | Rate limiting, MFA, защита от credential stuffing | Реализовать rate limiting и MFA для `/login` |
| 2 | Spoofing | `Внешняя платёжная система` → `processing-service` | Внешняя ИС отправляет webhook сообщения о платеже | Возможно подделать webhook и выдать себя за иную платёжную систему | Атакующий отправляет webhook, структуры и формата платёжной ИС, но с своими значениями, например с поддельным идентификатором и статусом успешной оплаты. Если источник и подпись не проверяются, система принимает событие как валидное | Высокая - возможна некорректная смена статуса платежа или запуск дальнейшей обработки | Добавить криптографию для проверки webhook через подпись, mTLS | Реализовать обязательную проверку подписи для всех входящих webhook + mTLS |
| 3 | Tampering | `processing-service` -> `kafka` | Kafka передаёт события о транзакциях и антифроде между компонентами системы | Несанкционированный producer или сервис с избыточными правами может создать или изменить значимое бизнес-событие | Скомпрометированный сервис публикует ложное событие transactions.created или событие с изменёнными суммой, статусом или идентификатором транзакции | Высокая — нарушение целостности платёжного процесса | mTLS, Kafka ACL | Архитектура: внедрить service identity и topic-level ACL для Kafka |
| 4 | Information disclosure | `card service` - `postgres` | Данные карт хранятся в Postgres в открытом виде | Несанкционированный доступ к БД приводит к раскрытию данных карт | Атакующий получает доступ к PostgreSQL через компрометацию сервиса, SQl-inj или через компрометацию учётных данных БД  и читает данные в открытом виде | Критическая — компрометация платёжных данных всех пользователей | Не хранить данные карт в открытом виде, использовать шифрование, ограничить доступ БД путём добавления RBAC | Зашифровать все данные карт в БД + ключи шифрования хранить в специальном хранилище (Vault)
| 5 | Tampering | `Пользователь` -> `auth-service` -> `postgres` | На сервере аутентификации отсутствует валидация входных данных и используются sql-запросы к postgres через конкатенацию | Атакующий может использовать атаку SQL-inj | Через SQL-inj атакующий может взять данные из таблицы users, и использовать их в дальнейшем для аутентификации, также можно скомпрометировать все таблицы БД | Критическая - компрометация УЗ пользователей и других данных таблиц БД | Параметризированные SQL-запросы к БД, RBAC в БД | Реализовать параметризированные запросы к БД или использовать ORM |
Тут можно описывать много сценариев: DDoS, данные ходят в открытом виде через HTTP, уязвимости JWT, уязвимости загрузки файлов аватара через профиль и т.д...

## Пример прохода через схему: Information Disclosure

В рамках углублённого анализа рассматривается домен "I".

| № | Элемент | Какие данные | Возможная угроза домена I |
|---|---|---|---|
| 1 | `Пользователь → nginx` | API-запросы, credentials, JWT | Утечка credentials или токенов |
| 2 | `Мерчант → nginx` | Платёжные запросы | Раскрытие данных платежа |
| 3 | `Внешняя платёжная система → nginx` | Webhook, статус платежа | Раскрытие данных callback |
| 4 | `nginx → Auth Service` | Логин, пароль, данные 2FA | Утечка учётных данных |
| 5 | `Auth Service → PostgreSQL` | Пользовательские данные, password hashes | Несанкционированное чтение данных |
| 6 | `Auth Service → Redis` | OTP, session state | Утечка OTP или данных сессии |
| 7 | `Processing Service → Kafka` | Данные транзакций | Несанкционированный consumer читает события |
| 8 | `Antifraud Service → Kafka` | Результаты антифрода | Раскрытие информации о проверках |
| 9 | `Services → PostgreSQL` | Персональные данные (PII), транзакции, баланс | Избыточный доступ сервисов к данным |
| 10 | `Card Service → PostgreSQL` | **PAN, CVV, срок действия** | **Утечка платёжных данных в открытом виде** |
| 11 | `Services → MinIO` | Документы, медиа | Несанкционированный доступ к файлам |
| 12 | `admin-panel → PostgreSQL` | Данные пользователей | Массовый доступ к пользовательским данным |
| 13 | `KYC → PostgreSQL / MinIO` | Документы и персональные данные | Утечка KYC-информации |
